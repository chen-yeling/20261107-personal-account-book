# 个人记账本——开发需求文档 v1.0

> 项目：10 人现场协作开发个人收支记账本  
> 技术方案：Python 3.10+ / Streamlit / 本地 JSON  
> 开发目标：2026-11-07 17:00 前完成可演示版本并发布 GitHub Release；23:00 前提交博客。  
> **接口基准**：《个人记账本_开发规范_v1.0.md》。如出现差异，以该开发规范的字段、公开函数签名和返回值为准。  
> 范围原则：优先完成基本功能；不要求登录、云端同步、复杂账户管理或数据库。

## 1. 项目目标与用户

开发一个可在本机启动的 Web 记账工具。用户可以录入收入和支出，查看近期明细，并按照日期、类别、金额及收支类型筛选数据，获取对应的收入、支出和结余统计；数据保存在本地文件，重启后可恢复。

- **目标用户**：需要简单记录个人日常收支的单个本地用户。
- **交付形态**：运行 `streamlit run app.py` 后在浏览器中操作的 Web 界面。
- **数据范围**：仅记录个人收支明细；不涉及银行账户关联、多人账号或联网服务。
- **验收重点**：实际可运行、数据正确、10 人各自独立完成模块并有真实 GitHub 提交。

## 3. 数据需求与统一字段

数据文件：`data/records.json`，UTF-8 编码，根结构必须是 **JSON 数组**；没有记录时为 `[]`。

每条记录统一采用以下 **7 个字段**，禁止自行更名、增删字段或将支出金额改为负数：

```json
{
  "id": "e19b216d8b364be89dc9e2492ef08aca",
  "date": "2026-11-07",
  "type": "expense",
  "amount": 25.5,
  "category": "饮食",
  "note": "午餐",
  "created_at": "2026-11-07T06:30:00+00:00"
}
```

| 字段 | 类型与约束 | 说明 |
|---|---|---|
| `id` | `str`，UUID4 的 32 位十六进制字符串 | 唯一 ID，创建时自动生成，修改时不变 |
| `date` | `str`，有效 `YYYY-MM-DD` 日期 | 用于业务日期筛选与排序 |
| `type` | `"income"` 或 `"expense"` | 分别代表收入、支出 |
| `amount` | 正数，最多两位小数，以 JSON 数字保存 | 单位：元；不带 `¥` |
| `category` | 必须为对应收支类别 | 使用 `models.py` 定义的类别常量 |
| `note` | `str`，0～200 字符 | 允许空字符串 |
| `created_at` | 带时区 ISO 8601 字符串 | 创建时自动生成，同日排序的辅助字段 |

统一类别：

```python
EXPENSE_CATEGORIES = ["饮食", "交通", "购物", "娱乐", "住房", "医疗", "学习", "其他"]
INCOME_CATEGORIES = ["工资", "兼职", "奖学金", "奖金", "其他"]
```

数据规则：

1. `type` 只存英文枚举，界面可以展示中文“收入”“支出”。
2. `category` 要与 `type` 匹配；类别列表以 `models.py` 为唯一来源。
3. 金额必须严格大于零；统计金额按两位小数输出。
4. 仅 `storage.py` 允许读写 `data/records.json`；损坏文件应报错，不能静默清空覆盖。
5. `data/records.json` 为个人本地数据，不提交 Git；可提供 `data/records.example.json` 示例文件。

### 4.1 对外接口精确定义

以下为接口摘要，**完整参数签名以《个人记账本_开发规范_v1.0.md》第 3 节为准**。组员不得自行改变参数名称、默认值、返回类型或返回字段。

| 接口 | 输入 | 输出 / 副作用 |
|---|---|---|
| `create_record(date, record_type, amount, category, note="")` | 日期、类型、金额、类别、备注 | 完整 `dict`，自动生成 ID / 创建时间 |
| `validate_record(record)` | 完整记录 `dict` | 合法时 `None`，不合法时 `ValueError` |
| `load_records()` | 无 | `list[dict]`，文件不存在返回 `[]` |
| `save_records(records)` | `list[dict]` | `None`，将全部记录写入 JSON |
| `add_record(date, record_type, amount, category, note="")` | 用户输入 | 完整记录 `dict`，并持久化 |
| `get_recent_records(records, limit=10)` | 记录列表、数量 | 排序后新列表 |
| `filter_records(records, start_date=None, end_date=None, category=None, record_type=None, min_amount=None, max_amount=None)` | 记录及筛选参数 | 筛选后按日期倒序的新列表 |
| `calculate_summary(records)` | 记录列表 | `{"income": float, "expense": float, "balance": float, "count": int}` |
| `category_totals(records, record_type="expense")` | 记录、收支类型 | `{类别: 金额}` 字典 |
| `render_charts(records)` | 记录列表 | 在 Streamlit 页面绘图，返回 `None` |
| `update_record(record_id, updates)` | 记录 ID、允许修改的字段字典 | 更新成功 `True`，未找到 `False` |
| `delete_record(record_id)` | 记录 ID | 删除成功 `True`，未找到 `False` |
| `export_csv(records)` | 记录列表 | CSV 格式 `bytes`，列序 `id,date,type,amount,category,note,created_at` |

### 4.2 模块边界

- `app.py`：只负责 UI 和业务编排；不直接打开 JSON。
- `models.py`：不导入其他项目模块；维护字段校验和类别常量。
- `storage.py`：唯一 JSON 读写模块；可以使用 `models.py` 校验。
- `add_record.py`、`manage_records.py`：通过 `models.py` 和 `storage.py` 操作数据。
- `view_records.py`、`filter_records.py`、`statistics.py`、`export_data.py`：针对传入的记录列表工作，不自行读写 JSON。
- `charts.py`：读取传入记录并复用统计模块计算结果。
- **禁止循环导入**，尤其不能让业务模块导入 `app.py`。
